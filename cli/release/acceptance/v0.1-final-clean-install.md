# Climb v0.1 final clean-install acceptance

Recorded 2026-08-28 after the release-generated proof was published and its
publication receipt was independently verified.

## Clean Linux container

The released CLI was installed in a disposable container based on:

```text
ghcr.io/astral-sh/uv:0.12.7-python3.12-trixie
```

Before installation, `command -v techtree` found no executable. The package
was then installed without a package cache using the published coordinate:

```sh
uv tool install --no-cache --python 3.12 'techtree==0.1.0'
```

The resulting executable was `/usr/local/bin/techtree`, and
`techtree --version` returned `0.1.0`.

Release verification matched the published ReleaseCore:

```text
sha256:c92b602e8097a6498c49f52587a486f46f2cfd0a7adfe5cb082c5e98527e40a1
```

Every applicable check passed. The three Skill-byte checks were skipped as
expected because those files are not carried in the CLI wheel. The container
used `--rm` and was removed when the rehearsal ended. Its downloaded base image
remained in the local Docker cache.

## Pinned Hermes plugin on the macOS host

The installed v0.1.0 plugin at release revision
`db827e714094c89514ea63d3ace1c97e6698589d` passed:

```sh
hermes plugins doctor techtree --ci
```

Runtime discovery, manifest parsing, import, and registration all passed. The
plugin registered 17 tools and 2 hooks.

## Fresh Hermes process

A new Hermes CLI process using profile `test2` loaded the plugin after its
installation. In that new process, `/techtree setup` returned:

```text
Plugin 0.1.0, release climb-v0.1.0.
Techtree CLI: 0.1.0
Doctor: ready
Next: Browse the Climbs this build offers
```

The process was then exited and its temporary tmux session was removed.

## Acceptance result

The public CLI installs from an empty Linux environment, verifies the pinned
release, and is discovered by a genuinely new Hermes process through the
pinned plugin. No code change, additional paid inference, or additional proof
publication was required for this rehearsal.
