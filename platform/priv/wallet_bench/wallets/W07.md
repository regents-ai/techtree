# Foundry Cast (W07)

- **Official entrypoint:** https://getfoundry.sh/introduction/installation (Foundry's installation guide).
- **Package:** the Foundry release from GitHub `foundry-rs/foundry`, installed by `foundryup`. The tested command is
  `cast`. The survey of 1 October 2026 installed v1.8.3.
- **What the guide tells an agent to do:** `curl -L https://getfoundry.sh/install | bash` installs `foundryup` into
  `~/.foundry/bin`; then restart the shell (or `source ~/.bashrc`) and run `foundryup` to install `forge`, `cast`,
  `anvil` and `chisel`. `foundryup` checks each download's SHA-256 against the release's GitHub attestation by itself;
  only `--force` (or `FOUNDRYUP_IGNORE_VERIFICATION=true`) skips that, and the script labels it insecure. Other routes:
  release binaries, Docker, building from source.
- **PATH:** `~/.foundry/bin` is not on the account's PATH until the shell settings are changed; an agent must add it
  or call the tools by full path.
- **What needs a person:** nothing to install. Making a keystore (`cast wallet new` or `cast wallet import`) asks for a
  password, which should come from the person rather than be typed into the conversation. Funding is out of scope.
- **Custody:** `cast wallet new` makes a key on the machine with no vendor account. Keystores are encrypted JSON files
  in `~/.foundry/keystores`, unlocked by their password; the guide warns the `~/.foundry` folder may hold private
  keys. There is no recovery service: the keystore and its password (or the raw key) are the only way back.
- **Chains:** any EVM chain reachable through an RPC address given to Cast. No Solana support.
- **Signing:** `cast wallet sign` makes an EIP-191 personal signature; `cast wallet verify` checks one.
