# MoonPay (W03)

- **Official entrypoint:** https://agents.moonpay.com/skill.md (MoonPay's agent skill page, linked from
  https://agents.moonpay.com/llms.txt). MoonPay publishes no "tell your agent" sentence.
- **Package:** npm `@moonpay/cli`, giving the commands `mp` and `moonpay`. The tested command is `mp`. These notes
  describe 1.100.1 (9 October 2026): written from the survey of 1 October 2026, which installed 1.96.5, and brought
  to 1.100.1 on 13 October 2026 by comparing the two packages. The skill page carries its own document version
  (0.6.24), which is not the CLI's version. The bare `mp` package on npm belongs to someone else.
- **What the guide tells an agent to do:** install the CLI with npm and use `mp` for wallets, signing and MoonPay's
  online services. On this machine `npm install -g` is refused (the shared Node folder is not writable); the working
  route is `npm install -g --prefix "$HOME/.local" @moonpay/cli`, which puts `mp` in `~/.local/bin` on the account's
  PATH. In the survey npm blocked six native setup scripts (hardware-wallet and websocket speed-ups); `mp --help` and
  `mp --version` still worked. The skill page refuses some plain downloaders (HTTP 403); `curl` and web readers get it.
- **What needs a person:** nothing to install or to make a wallet. `mp wallet create` makes a wallet with no login,
  email code or browser step. MoonPay's online services need `mp login --email`, a browser hCaptcha and an emailed code;
  only a person can do that, and the wallet test does not need it.
- **Terms:** the CLI records MoonPay's Terms consent by itself (`~/.config/moonpay/consent.json`) the first time some
  commands run, such as the read-only `mp wallet list`, with no accept step. That is allowed and is not a failure; an
  agent that notices the file and says it cannot tell who accepted is reporting accurately.
- **Custody:** non-custodial HD wallets (BIP39) on the machine, encrypted with the operating system's keychain. With no
  keychain, as here, the CLI writes the wallet's unlock passphrase to a plain owner-only file,
  `~/.config/moonpay/.vault-passphrase`, beside the encrypted wallet, and shows no recovery phrase, so there is no
  backup beyond those files. There is no vendor recovery.
- **Chains:** MoonPay documents a named list, not every EVM chain: Solana, Ethereum, Base, Polygon, Arbitrum,
  Optimism, BNB, Avalanche, Tron and Bitcoin. The wallet has one EVM address, the same on each listed EVM chain. The
  CLI's own wallet listing also shows Robinhood Chain, Tempo, Arc and seven testnets, plus TON and Filecoin
  addresses.
- **Signing:** `mp message sign` makes an EIP-191 personal signature; `mp wallet list` shows the wallet's addresses.
