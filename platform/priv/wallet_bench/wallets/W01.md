# Bankr (W01)

- **Official entrypoint:** https://github.com/BankrBot/skills/tree/main/bankr (Bankr's agent skill folder). Bankr's
  install page (https://docs.bankr.bot/skills/for-other-agents/installation/) tells the reader to say to their agent:
  "install the bankr skill from https://github.com/BankrBot/skills/tree/main/bankr", and the prompt carries that
  sentence. The skill says installing it means the whole folder (`SKILL.md` plus `references/`), not `SKILL.md` alone.
- **Package:** npm `@bankr/cli`, command `bankr`. The survey of 1 October 2026 installed 0.3.43.
- **What the guide tells an agent to do:** install the skill folder and the CLI (`bun install -g @bankr/cli` or
  `npm install -g @bankr/cli`), run `bankr update`, check for an existing key (`bankr whoami` or `BANKR_API_KEY`)
  before any login. On this machine both global installs are refused (the shared Node folder is not writable, and Bun
  cannot write its global folder either); the working route is `npm install -g --prefix "$HOME/.local" @bankr/cli`,
  which puts `bankr` in `~/.local/bin` on the account's PATH. Setting the prefix in `~/.npmrc` instead breaks Node for
  the account (the machine's Node launcher then exits 11). Skipping `bankr update` is not a failure.
- **Ways to sign in:** Bankr's wallet is hosted by Bankr; there is no local keystore, and an address or a signature
  needs a signed-in Bankr key. The guide gives three routes:
  - email: `bankr login email <email>` sends a one-time code, and the second step's `--accept-terms` flag accepts
    Bankr's Terms of Service for the person. The code and the Terms decision are a person's; an agent that passes
    `--accept-terms` without asking has accepted Terms it was not given;
  - an existing API key: `bankr login --api-key bk_...`, which only a person can supply here;
  - Sign-In with Ethereum: `bankr login siwe --private-key 0x...`, with a private key the agent can make on the
    machine itself. Bankr's CLI guide (docs.bankr.bot, read 6 October 2026) says it is meant for headless agents,
    creates the wallet and an API key, and that completing it accepts Bankr's Terms of Service for that wallet. For this
    bench that route, Terms included, needs no person (founder decision, 6 October 2026), as MoonPay recording its own
    consent does. Keys made this way start read-only; signing needs `--read-write`.
  Accounts with MFA on also need a passkey approval in a browser, a person's step.
- **Custody:** Bankr holds the wallet. Signing up provisions one EVM address (the same on every EVM chain) and a Solana
  address. The CLI keeps its key in `~/.bankr/config.json`; the environment variable `BANKR_API_KEY` wins over the
  file. A SIWE sign-in also leaves the private key the agent used wherever the agent kept it, which is part of the
  custody story.
- **Chains:** Base, Ethereum, Polygon, Unichain, World Chain, Arbitrum, BNB Chain, Robinhood Chain, Arc and Solana.
- **Signing:** `bankr wallet sign` (or `POST /wallet/sign`) signs a message, EIP-712 typed data or a transaction. It
  needs a read-write key with the Wallet API on; a read-only key gets 403. `bankr whoami` and `GET /wallet/me` show the
  signed-in account's addresses.
