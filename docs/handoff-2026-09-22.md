## 4. Proposed next release: 0.2.2

On 2026-09-22 the founder passed on Astra's proposal (Astra is a ChatGPT
thread the founder consults; its notes are advice, not orders). The
outgoing thread checked it against the code and endorsed it. Summary:

**0.2.2 is the release that lets an outside developer decide whether to keep
a Skill.** Gate: two outside developers complete the workflow on their own
repositories without engineering help and can say keep / revise / discard.
Positive improvement is not required. This is the same "external
reproduction first" priority already in `docs/handoff-2026-09-19.md` §3.2.

Items, in the order the outgoing thread recommends building them
(4 → 2 → 3 → 1), with what the code already has:

4. **Reliable installation and release preparation.** Pin the build backend
   (`cli/pyproject.toml` `[build-system] requires = ["hatchling"]` is
   unpinned; hatchling 1.32.3 vs 1.32.4 made the first 0.2.1 wheel
   non-reproducible, differing only in WHEEL/RECORD). Reconcile the tested
   Hermes versions (`cli/release/release-inputs.json` → release core
   `maximum_tested_host_hermes_version`, and the bootstrap
   `minimums.hermes_version`, both `0.20.1`; qualified on 0.21.3). Make a
   missing sign-in or incompatible setup easy to resolve (the runner already
   refuses `forge_profile_missing` / `forge_profile_signed_out` and names the
   command; `techtree doctor` reports the profile's presence only). Small.
2. **Task selection and qualification feedback.** `cli/src/techtree/forge/qualify.py`
   already records per-task checks (image builds, workspace clean, no
   verifier material in the image, at least one fail-to-pass test, control
   scores 0.0, reference scores 1.0). Missing: plain-language output saying
   which repairs became tasks, why the others were rejected, and a warning
   when too few remain for a useful comparison. Also: qualify several varied
   public repositories so the example set is broader than one task. Moderate.
3. **Decision-grade reports.** `forge/compare.py` and `forge/report.py`
   already pair every task × repetition (`spec.sampling.repetitions`) and
   show won/lost/tied per pair, time, model calls, tokens, reported cost,
   allowed differences, and "Partial" until every pair has a verdict.
   Missing: calling out regressions (a higher average must not hide one),
   consistency across repeated attempts, and an explicit "inconclusive"
   when the evidence is thin. Moderate.
1. **Guided "evaluate this Skill on my repository" flow.** One entry point
   walking prerequisites → repository → task qualification → baseline →
   candidate → report, showing what leaves the machine, what will run, and
   the limits before anything starts. Each step already previews and asks
   individually (`forge run`, `uplift start`); the single walk-through does
   not exist, and the Hermes plugin (`plugin/`) needs the same experience.
   Largest item; build it last so it can use 2 and 3.

**0.3.0** (Astra's version): one complete Foundry workflow — separate
practice / selection / proving tasks with proving answers hidden from the
improving agent; bounded automatic Skill improvement with every candidate,
parent, result and selection reason recorded; private-repository evaluation
with disclosure controls; an inspectable, reproducible Skill history. Gate:
one customer completes the full cycle with no proving-data leakage. This is
a narrower delivery order of the existing Foundry epic
(`docs/plan/techtree-market.md` "v0.3", `techtree-8dj.1–.7`), not a new
plan. Nothing to decide yet.

## 7. Gotchas learned on this lane (in addition to the 0.2.1 packet's §8)

- Wheels are only reproducible from a clean detached checkout; the build
  environment of the release worktree differed by one hatchling patch
  version and the publish workflow refused the hash. Pinning is 0.2.2 item 4.
- The Hermes experiment profile must be created with `hermes profile create
  techtree --no-alias`; sign-in is `hermes -p techtree auth add PROVIDER`
  and only the person can do it. Named profiles do not inherit the root's
  sign-in (Hermes #111724); never copy or link tokens.
- On macOS, never tar Skills without `COPYFILE_DISABLE=1` (AppleDouble
  `._` files are correctly refused by the CLI).
- `gpt-5.3-codex` is refused by the ChatGPT-account backend; use
  `gpt-5.6-sol`. A real attempt on the one qualified task takes 170–230 s.
- The desktop app's tool guards refuse `sleep N && …` chains; use
  `until … done` loops. `file://` does not open in the browser pane;
  register a temporary `python3 -m http.server` launch entry.
